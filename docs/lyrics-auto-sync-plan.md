# AI 歌詞自動同期（段階2）実装計画（案・未承認）

作成：2026-10-24。本番の変更・AI 解析・デプロイは、この計画の承認後に段階ごとに改めて承認を取る。

## 0. 現状（2026-10-24 本番を読み取りだけで確認）
- 楽曲 10曲（すべて公開中・すべて歌詞あり・すべて MP3・4.8〜7.0MB・3分43秒〜5分31秒、合計 47分04秒）
- 同期データ（`track_lyrics_sync`）0件。列：lines / source（manual・auto・mixed）/ lyrics_hash / updated_by / updated_at
- 投稿：会員がアプリから `tracks` に直接 insert → `tracks_before_insert` で status=pending に固定 → 管理者が承認して public
- 歌詞を投稿後に変えられるのは管理者だけ（`tracks_update_admin`）。投稿者が歌詞を直す画面は今は無い
- 長さ（duration）は投稿時にアプリが測って保存。測れなかった曲は再生時に `set_duration_if_missing` で後から入る
- 投稿できる音源：MP3・WAV・M4A、50MB まで
- 使える仕組み：pg_cron・pg_net・Vault（退会処理と同じ「定期実行 → 合言葉付きで Edge Function を呼ぶ」形が既にある）
- 注意：この DB では service_role に表の直接の読み取り権限が無い → Edge Function からは読み取り・書き込みとも SECURITY DEFINER の関数経由
- 検証の結果（おぼろ月）：vad_filter=false で 65／65行（中盤も 100%）、AI の処理 27秒、約201ニューロン

## 1. 全体の流れ
```
投稿・承認・歌詞の変更（tracks） ──トリガー──▶ 解析待ちの列（lyrics_align_jobs）
                                                    │
pg_cron（5分ごと）── 合言葉付き ──▶ Edge Function「lyrics-align」
                                    ① 1件だけ取り出す（同時に1件・その日の使用量を先に予約）
                                    ② 音源を取り出す → Workers AI（vad_filter=false）
                                    ③ 歌詞と照合 → 保存の関数（検証・上書きの規則を DB 側で強制）
                                    ④ 失敗 → 理由ごとに再試行の予定を入れる（同期データは触らない）
再生画面：これまでどおり lyrics_sync_get で読み、時刻どおりにハイライト（変更なし）
```

## 2. データベース（v1.15・追加のみ）
| 追加するもの | 内容 |
|---|---|
| 表 `lyrics_align_jobs` | 曲ごとに1行：状態（waiting / queued / running / done / review / failed / skipped）、理由、試行回数、次に試す時刻、解析時の lyrics_hash、見積もりニューロン、AI の提案（proposal）、照合率、作業中の札（token・期限） |
| 表 `lyrics_align_budget` | UTC の日付ごとの予約量・使用量・回数（Cloudflare の無料枠は UTC 0時に戻る） |
| トリガー（tracks の insert・lyrics / status / duration の変更） | 解析待ちに登録するだけ（通信はしない）。中で失敗しても投稿・承認は止めない |
| 仕事用の関数（service_role だけ） | `lyrics_align_claim`（1件取り出し＋予約）、`lyrics_align_finish`（保存）、`lyrics_align_fail`（失敗の記録）、`lyrics_align_secret_matches` |
| 投稿者・管理者用の関数 | `lyrics_align_status`（状態を見る）、`lyrics_align_request`（作り直しを頼む）、`lyrics_align_apply`（AI の提案を採用）、`admin_align_overview`、`admin_align_enqueue_existing` |
| 既存の変更（最小） | `lyrics_sync_save`：AI が作った同期（auto）を投稿者が直して保存したら source を mixed にする（＝以後 AI は上書きしない）。検証部分を共通の内部関数に切り出し、AI の保存も同じ検証を通す |

新しい表は RLS を有効にし、未ログイン・会員には権限を付けない（関数経由のみ）。

## 3. 既存曲の一括解析
1. v1.15 を適用（この時点では止めた状態：Edge Function の `AIMUSE_ALIGN_ENABLED` が未設定なら何もしない）
2. 管理者が `admin_align_enqueue_existing` を実行 → 歌詞があり、手動の同期が無い公開中の曲を解析待ちに登録
3. まず1曲（おぼろ月）だけ動かして結果を確認 → 承認後に残り 9曲
4. 5分ごとに1曲ずつ処理。10曲で約50分、合計 約2,200ニューロン（1日の上限の内側）
5. 1日の上限に達したら翌日（UTC）に自動で続きから

## 4. 新しく投稿された曲の自動解析
- 解析を始める時点（要決定）：
  - **案A（おすすめ）承認されて公開になったとき**：却下される曲に無料枠を使わない。審査前の音源を外部（Cloudflare）に送らない。同期が見えるのは公開後なので困らない
  - 案B 投稿した時点（審査待ち）：承認後すぐ同期済み。ただし却下曲にも枠を使い、審査前の音源を外部に送る
- 長さが未登録（0秒）の曲は「待ち」にし、長さが入った時点で自動で解析待ちへ
- 歌詞が無い曲は「歌詞待ち（waiting）」。歌詞が登録・変更されたら（lyrics_hash が変わったら）自動で解析待ちへ
- 20MB を超える音源（長い WAV など）は解析しない（「手動で合わせてください」と表示）

## 5. 無料枠の管理
| 制限 | 値（案） | 理由 |
|---|---|---|
| 1日の上限（予約ベース） | 6,000ニューロン（無料枠 10,000 の 60%） | 検証・作り直しの余裕を残す |
| 予約の見積もり | 長さ（秒）÷60×46.63×1.2 | 実際の使用量を読めないため2割の余裕 |
| 同時に解析する数 | 1件 | 取り出しを DB のロックで1件に限定 |
| 1回に処理する数 | 1件／5分 | 1日最大 288回。上限で先に止まる |
| 1曲の長さ | 10分まで | 1曲 最大 約560ニューロン |
| 作り直しの依頼 | 1曲 1日2回・1人 1日5回 | 無料枠の取り合いを防ぐ |
| Cloudflare が「上限」と返したとき（FREE_LIMIT） | その日の残りは全部止めて、翌日（UTC）に再開 | 課金は発生しない（無料プランは超過分を請求しない） |

- 予約は解析の前に行い、終わったら実際の音声の長さで確定。失敗しても予約分はその日の使用量として数える（安全側）
- 重要：Cloudflare を有料プラン（Workers Paid）にしない限り請求は発生しない。運用中もプランは無料のまま
- 実際の使用量は Cloudflare の画面で確認（今のトークンでは読めない。読む場合はトークンに「Account Analytics 読み取り」を追加 ― 任意）

## 6. 解析失敗時の安全な停止と再試行
| 失敗 | 対応 |
|---|---|
| 音源を取り出せない・AI の一時的な失敗・時間切れ | 30分後 → 2時間後 → 24時間後に再試行。3回失敗で failed（手動で合わせる案内） |
| FREE_LIMIT（無料枠切れ） | 試行回数に数えず、翌日 UTC 0時以降に再開。その日の処理は全部止める |
| AI_AUTH（トークン無効） | すべての解析を止め、管理画面に表示（運営者がトークンを直すまで再開しない） |
| 歌詞・長さが無い、20MB 超、10分超 | 再試行しない（skipped / waiting）。条件が変われば自動で再登録 |
| 解析中に歌詞が変わった | 結果を捨てて、新しい歌詞で解析待ちへ |
| 作業中のまま止まった（10分以上） | 自動で解析待ちに戻す（試行回数 +1） |
| 照合率が低い（60% 未満・案） | 自動で表示せず「要確認（review）」として提案だけ保存。投稿者が確認して採用 |

どの失敗でも、同期データ・歌詞・楽曲は書き換えない。再生画面は同期が無ければ今と同じ「歌詞をそのまま表示」になる。

## 7. 手動修正との共存（上書きの規則は DB の関数で強制）
| 今の同期 | AI の結果の扱い |
|---|---|
| 無い | 自動で保存（source=auto）し、再生でハイライト |
| auto（AI のまま） | 歌詞が変わったときだけ作り直して置き換える |
| manual（手動）・mixed（AI を手で直した） | **上書きしない**。提案として保存し、投稿者に「AI の結果があります」と表示。投稿者が「採用」を押したときだけ置き換える |

- 投稿者は今の編集画面（タップで合わせる・±0.1秒・全体をずらす）で AI の結果をそのまま直せる。直して保存すると mixed になり、以後 AI は上書きしない
- 「AI で作り直す」ボタン：結果は提案として届き、採用するまで今の同期はそのまま
- 保存の直前に、行を固定して「手動の同期が先に保存されていないか」「歌詞が変わっていないか」を確かめる（取り違え防止）

## 8. セキュリティ
- Edge Function `lyrics-align` は合言葉（Vault）付きの定期実行からだけ動く。会員・未ログインは呼べない（401/403）。Verify JWT はオフにして関数の中で確認（今の退会処理と同じ）
- 仕事用の関数は service_role だけが実行できる。投稿者用の関数は「本人の曲か・管理者か」を関数の中で確認
- Cloudflare のトークンは Edge Function の Secrets にだけ置き、返す内容・記録に含めない。権限は Workers AI だけ
- 新しい表は直接読めない（関数経由のみ）。AI の提案は本人と管理者だけが見られる
- 検証用の `lyrics-align-probe` と関数3つは、本番の仕組みが動いたら片付ける
- 音源と歌詞を Cloudflare に送るため、**一般公開の前にプライバシーポリシーへ追記が必要**（送信先・目的・保存しないこと）
