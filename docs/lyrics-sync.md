# 歌詞の同期（段階1：時刻の保存・同期表示・手動修正）

## 以前の問題
- 歌詞は1行ずつの文字だけで、時刻がありませんでした。表示する行は「再生位置 ÷ 曲の長さ × 行数」で決めていたため、
  イントロでも進み、間奏で先に行き、後半ほどずれが大きくなりました。`[Verse 1]` などの見出しも1行として数えていました。

## 段階1の仕組み
- **データベース（v1.14 `migration_v1_14_lyrics_sync.sql`）**：表 `track_lyrics_sync` に、曲ごとの各行の歌い出し `t`
  （と、間奏の前の歌い終わり `e`）を保存します。楽曲・歌詞（`tracks.lyrics`）には手を加えません。
  - 読み書きは関数だけ：`lyrics_sync_get`（その曲が見える人なら誰でも）・`lyrics_sync_save`（投稿者本人と管理者）
  - 時刻を作った後に歌詞が変わると `stale`（要確認）になり、アプリはその同期を使わず全文表示にします
  - 元に戻す：`supabase/rollback/rollback_v1_14.sql`
- **再生画面**：音源の現在の時刻から「歌い出しを過ぎた最後の行」を表示します（0.15秒だけ早め）。
  一時停止・シーク・途中からの再生・再生速度の変化でも、時刻をそのつど音源から読むので、ずれが溜まりません。
  - 最初の歌い出しより前（イントロ）と、歌い終わり `e` の後（間奏・終わり）は、どの行も光らせません
  - 見出し（行全体が `[ ]` か `【 】`）は小さな区切りとして表示し、時刻は付けません
  - 同期が無い曲・要確認の曲は、歌詞を全文表示するだけです（推測で光らせない）
  - 自動スクロールは歌詞の枠の中だけ。指で歌詞を動かしたあと4秒間は止めます
- **編集画面（歌詞の同期）**：マイページの投稿曲の「歌詞の同期」ボタン、または再生画面の歌詞の下から開きます。
  曲を流しながら歌い出しでボタンを押すと記録されます（押すまでの遅れ 0.2秒を補正）。「歌が止まる（間奏）」、
  各行の ±0.1秒、全体の ±0.1秒、「▶ 確認」（その行の2秒前から再生）、再生速度 1・0.75・0.5倍。
  「保存する」まではデータベースに送りません。

## 段階2（AI 自動同期）に向けて
- 表の `source`（manual / auto / mixed）と、行ごとの形式（`i`・`t`・`e`）は、自動で作った時刻もそのまま入れられる形にしてあります。
- 自動で作った時刻は「下書き」として編集画面に読み込み、投稿者が確認・修正してから保存する流れにする予定です。
